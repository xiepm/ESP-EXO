# ESP-EXO 网页上位机操作说明

适用：仓库固件 **0.10.13** 和配套五栏目网页；2026-10-14按源码、协议和测试核对。
硬件：ESP32-S3-N16R8、两台RobStride RS01；当前工程CAN为TX GPIO4、RX GPIO1、1 Mbit/s，
执行器A的CAN ID为0x10，B为0x20。LEFT/RIGHT由装配配置决定，不能由CAN ID猜左右腿。

这是开发调试版本的操作说明。阶段10整体仍未完成；2026-10-13已记录运动中CAN错误
触发停机，电气根因尚未证实。历史烧录或通信通过不能代替本次设备在线、方向及零位确认。
见[当前验收记录](../phase10/PHASE_10_ACCEPTANCE.md)和[助力中断诊断](../phase10/PHASE_10_ASSIST_INTERRUPTION_20261013.md)。

## 1. 启动网页

Windows上使用支持Web Bluetooth的Chrome或Edge，打开蓝牙。网页依赖Node.js >=22.13.0。

首次安装依赖，在PowerShell运行：

```powershell
Set-Location 'D:\ESP32\esp_can\web-bluetooth-console'
npm.cmd ci
npm.cmd run local
```

已有依赖时只运行最后一条命令；也可双击网页目录内的`start-local.cmd`。
使用期间保持服务窗口运行。按Ctrl+C会停止网站服务。

打开 **http://localhost:4173/exo**。根路径`/`是原通用终端，应使用`/exo`产品界面。
本地服务只监听127.0.0.1；手机不能把电脑的localhost当成电脑地址。
手机访问需要另行配置可信HTTPS及浏览器蓝牙支持，本仓库本地启动命令没有部署手机网站。

看到`ERR_CONNECTION_REFUSED`通常是本地服务未启动或已退出；先查看服务终端，而不是重新烧录主控。

## 2. 五个栏目与完整流程

| 栏目 | 用途 | 应看到的结果 |
| --- | --- | --- |
| 连接 | 蓝牙连接、固件身份、主控状态、CAN与反馈诊断 | 连接成功；两侧有新反馈；主控状态已读取 |
| 设置 | 出厂前抬方向示教、本次穿戴零位校准或沿用 | 方向有效；本次双髋零位有效 |
| 运动 | 选择助力策略、参数与左右等级，保存，START/STOP | 设备读回与草稿一致；启停达到最终状态 |
| 实时数据 | 双髋信息、实时示波器、步态及助力状态 | 新遥测持续更新；无效数据明确显示“—” |
| 数据记录 | 按日期查看本地步态摘要，导出原始遥测和通信日志 | 记录可查，重要数据已导出备份 |

首次装配：连接 → 核对双电机反馈 → 出厂方向示教 → 中立位校准 → 配置并读回 → 启动 → 查看/记录 → STOP并确认待机。
之后穿戴：连接 → 核对反馈和已保存方向 → 选择沿用或重新校准 → 配置并读回 → 启停和记录。
切换栏目不会启动或停止外骨骼。网页只配置、启停和显示，100 Hz控制在主控本地运行。

## 3. 连接：先区分蓝牙在线与电机在线

1. 打开外骨骼主控、CAN模块及电机所需电源。USB是否接入不应代替外部供电核对。
2. 点击“选择ESP-EXO”，在浏览器设备选择弹窗选中设备并配对。
3. 等待GATT连接、Product Service发现、响应订阅及初始状态读取完成。
4. 核对页面读回的固件版本。新版功能由固件能力和读回值共同解锁；草稿不等于已生效。
5. 在“电机反馈与CAN诊断”查看CAN状态、收发错误计数和双电机反馈。

“已配对”只表示操作系统记住设备，不代表网页已建立GATT连接；蓝牙连上主控也不代表
两台电机的CAN反馈正常。角度全零或“请求上报成功”不能单独证明电机在线。

“重试已选设备”用于重连已选择的蓝牙设备。“恢复电机反馈”只请求状态上报，
不使能、不启动电机；仅在主控待机且CAN门禁满足时可用。提交成功后仍须等到两侧新反馈。

一次主控通常由一个BLE客户端连接。连接失败时先断开其他网页、手机或BLE工具中的连接，
再重试。主控重启/烧录后应重新连接并读取身份，不沿用旧页面缓存状态。

## 4. 设置：出厂方向与穿戴零位分开

### 4.1 出厂配置：标定“向前抬腿为正”

首次装配、更换电机或调整安装方向后执行。需主控IDLE、双电机REST、有新鲜反馈。

1. 双腿回中立位并保持静止，点击“记录左腿静止基准”。
2. **手动向前抬左腿约5～15°**，另一腿保持原位；停稳后点击“确认前抬方向”。
3. 等待主控保存及网页读回，左腿回中立位。
4. 按同样流程完成右腿，核对左右方向均有效。

这一步根据真实原始角变化学习正负号，不由电机ID推断。主控不能判断操作者实际抬的是
前方还是后方，须按说明前抬。方向同时用于人体角度、速度、力矩与最终电机命令的转换。

方向写入主控NVS，断电保留。示教会使相关旧零位失效，之后重新校准穿戴零位。
同CAN ID更换另一台电机不能自动识别，需重新标定。此流程本身不驱动电机。

### 4.2 重新校准：把当前左右位置同时定义为0°

1. 完成穿戴并扶稳，双髋回到本次中立位，保持静止。
2. 在“本次零位选择”选“重新校准”，核对出厂方向和双侧反馈有效。
3. 勾选“我已确认穿戴完成，双髋处于中立位并保持静止”。
4. 如需下次选择沿用，勾选“保存本次零位供下次沿用（断电保留）”。
5. 点击“校准并写入双髋零位”，保持静止直到读回结束。

固件一次采集左右当前位置并成对更新RAM零位；网页读取真实角度和偏置，
**两侧人体角及原始角减零位均在±0.5°内**才确认成功。不会仅把页面数字改成0。
原始电机角仍可能不是0°，这是正常的坐标偏置。

校准要求IDLE、双侧在线、反馈新鲜且静止，任一侧失败不会只更新另一侧。
按钮灰色时查看其下方原因，不应跳过门禁。软件零位不改变RS01机械零点。

### 4.3 沿用上次零位：恢复旧偏置，需要本次确认

只有曾成功保存过成对候选、且映射/方向等仍匹配时才能选择。

1. 当前穿戴回中立位，保持静止。
2. 选“沿用上次零位”，查看两侧沿用预览。
3. 勾选当前穿戴确认，点击“确认并沿用上次零位”，等待读回。

沿用保留旧偏置，**不会把当前位置重新定义成0°**。任一侧预览偏离超过5°或条件不满足，
改选重新校准。安装调整、更换电机或机械置零后重新校准。

| 数据 | 保存位置 | 重启后的行为 |
| --- | --- | --- |
| 出厂方向 | 主控NVS | 有效记录恢复；安装改变后重新示教 |
| 本次生效零位 | 主控RAM | 不自动恢复，需本次确认沿用或重新校准 |
| 上次零位候选 | 主控NVS（可选保存） | 保留，供操作者选择沿用 |
| 助力/模式配置 | 主控RAM | 回到默认；须读取设备当前值 |

“忘记已保存零位”删除候选，不改变本次RAM零位，也不删除出厂方向。

## 5. 运动：配置、读回，再单独启动

### 5.1 可选策略和执行方式

| 策略 | 当前行为 |
| --- | --- |
| 关闭附加助力/TRANSPARENT | 不生成附加助力；基础模式仍按配置执行 |
| 相位曲线/PHASE_PROFILE | 人体运动形成新的双侧髋事件并满足步态门禁后，按工程相位曲线计算力矩 |
| 摆腿事件脉冲助力/ANGLE_THRESHOLD | 本侧完成复位后，新的正向越阈事件触发一次sin²脉冲，左右独立 |

ASSIST_AS_NEEDED/AAN_RESIDUAL仍是未实现接口，不能当作可用策略。仓库相位曲线是
工程验证曲线，不是已复现的论文曲线。

执行方式另行选择：

- DISABLED：关闭策略输出。
- SHADOW（观察模式）：计算建议，实际新增助力为0。
- ACTIVE（真实助力）：门禁满足时将有界力矩叠加到最终命令。

ACTIVE仅允许底层DAMPING + CONSTANT，并要求适用的人体穿戴配置、方向、零位和
新鲜反馈等条件。SHADOW只保证附加助力为0；若另选工程主动轨迹，基础轨迹仍可驱动电机。

### 5.2 事件脉冲参数（0.10.13）

| 页面参数 | 范围/规则 | 作用 |
| --- | --- | --- |
| 前抬角度阈值 | 1～60°；默认10° | 复位后向正方向越过它，形成候选事件 |
| 最大附加助力力矩 | 0～15.000 N·m；默认0.500 | START时锁存的附加力矩上限 |
| 申请脉冲峰值 | 0～15.000 N·m，且不超过锁存上限 | 下一有效事件申请的峰值 |
| 左/右助力等级 | 各0～100% | 分别缩放本侧申请峰值；0%为零附加力矩 |
| FIXED固定时长 | 100～3000 ms；默认600 | 每次脉冲使用固定Ta |
| PERIOD_SCALED比例r | 0.1～0.6；默认0.3 | Ta=clamp(r×本侧可信周期T, Ta_min, Ta_max) |
| 缩放模式最短/最长时长 | 100～2000 ms，最短≤最长 | 默认150/1500 ms |
| 合理周期上下限 | 在300～5000 ms内且下限<上限 | 默认400/3000 ms，拒绝异常事件间隔 |
| 复位角 | −30°起，至少低于触发角1°；默认8° | 返回低角区并满足连续确认，才重新允许触发 |
| 允许前抬角上限 | 至少高于触发角2°，不超过90°；默认30° | 超出窗口立即退出脉冲 |
| 最大上升速率 | 固件0.10.13为20 N·m/s，不是网页可调项 | 限制本次冻结峰值 |

本侧一次助力为：

```text
u = (当前时间 − 本次触发时间) / Ta
τ = A × sin²(πu)          0≤u≤1
A = min(申请峰值 × 本侧等级/100, 20 × Ta秒/π)
```

这是人体坐标下的正向附加力矩；唯一电机命令出口再乘已标定方向。u是本次脉冲进度，
不是完整步态相位。左右分别估计同侧事件间隔，不要求强制交替或相差半周期。

600 ms脉冲受速率限制，100%等级下即使申请15 N·m，算法峰值最多约3.82 N·m；
3秒脉冲可冻结15 N·m，但正常行走中的反向/窗口退出可能发生在1.5秒峰值之前，
**不能保证每次运动实际达到申请峰值**。15 N·m和3秒是工程配置上限，不是已经通过的
人体使用参数或实测人体受力。

一次脉冲开始后A和Ta冻结。运行中通过“保存下一脉冲参数并读回”更新，A/Ta从下一事件生效；
窗口收紧即时生效，提前退出始终优先。整体策略、等级、最大上限和基础模式需先STOP回IDLE再改。

### 5.3 为什么没有下一次脉冲

每条腿一次确认周期最多触发一次；没有新事件就没有新脉冲。
结束或提前退出后，该侧需回到复位角以下持续约80 ms，再正向越过触发角并完成
约30 ms的持续前抬确认。反向、静止约100 ms、越出允许窗口或反馈失效会退出当前脉冲。

PERIOD_SCALED需要同侧至少两个合理事件间隔形成可信周期；初始学习、异常间隔或超时
期间不会用不可信周期生成助力。运动页的左右事件/脉冲状态显示等待复位、事件确认、
脉冲进行、退出原因和冻结峰值/时长，可用于区分正常等待与故障。

### 5.4 保存、START与STOP

1. IDLE下选择策略、方式及参数，点击“保存助力设置并读回”。
2. 核对“设备已保存”与草稿一致，确认本次方向、零位、反馈和启动门禁就绪。
3. 点击“START并等待RUNNING”，等待主控进入RUNNING且输出门开启。
4. 运动后点击“STOP并等待IDLE”或顶部“停止外骨骼”，等待最终待机/输出关闭。

ACK只表示请求被接收，不等于已完成。START灰色时按页面原因处理，常见为未连接、
主控ERROR、缺反馈、无本次零位、参数尚未读回或基础模式不满足ACTIVE。

关闭网页、断开BLE、暂停图表、停止遥测和结束记录都不等于STOP。
断连后先重连读取真实状态，再处理停止；STOP未能确认失能时，以切断动力电源处理现场。

## 6. 实时数据：示波器的使用与含义

完成连接和身份核对后进入“实时数据”，默认开启10 Hz六通道采集（角度、速度、相位、
置信度、建议助力和实际加入命令的助力增量；mask=0x007B）。未自动开启时点击“开始遥测”。

- 时间窗可选2/5/10/20/30秒，横轴使用主控时间。
- 可选自动/固定纵轴、LEFT/RIGHT曲线，展开单图；游标对齐各通道的真实样本。
- “暂停显示（继续采集）”只冻结画面，采集继续；恢复后回到实时滚动。
- “停止遥测（不停止外骨骼）”只关数据流；手动停止后不会反复自动重启。
- 修改5/10/20 Hz或通道组合时，先停止遥测，再重新开始。

角度单位°、速度°/s、力矩N·m。相位/置信度显示百分比；相位原点是编码器髋屈曲峰代理，
不等于足跟着地。电机反馈力矩是电机估计值；“实际加入命令的助力增量”是命令中的
附加量，不是人体力矩传感器测量。

“—”表示无有效数据，不能解释为0。曲线缺帧或无效时断开，不补零、不中间插造数据。
超过1.5秒无新遥测会显示中断，此时保留的只是历史波形。静止/未锁定时相位无效可能正常；
SHADOW实际附加量应为0。角度仍更新而助力长期无效时，同时检查主控状态和助力门禁。

10 Hz是当前默认。曾观察到运动时20 Hz多通道拥塞；全7通道20 Hz持续负载尚未通过，
不能把网页可选项当作所有组合已通过耐久验收。

## 7. 数据记录：日期摘要与原始数据分别保存

日期使用北京时间。主控RUNNING且输出许可开启后自动开始一段记录；退出运行、断连或
主控重启时结束。也可点击“开始观察记录”，只记录数据，不启动电机。

日期记录存于**当前浏览器IndexedDB**，约每秒记录一个新状态快照和摘要，非100 Hz原始
控制数据。可按日查看时长、有效步态比例、平均步频和双髋角曲线，导出本次CSV/JSON或
导入页面导出的JSON。跨日分段，单段最多三小时；异常关闭可能显示“未完整结束”。
当前不计算真实步数和距离。静止观察、工程轨迹和产品运动分别标记，不把工程轨迹当作
人体主动步态通过证据。

“本次连接的原始样本与通信日志”中另有：

| 导出 | 内容 | 保存边界 |
| --- | --- | --- |
| 遥测CSV/JSONL | 主控时间、样本/流序号、角度/速度/相位/助力及状态 | 本次内存采集，最多10000个时刻；刷新前导出 |
| 关节CSV | 兼容轮询的关节读回及反馈年龄等 | 本次内存快照，不等于连续遥测 |
| BLE JSONL | TX/Notify/错误、原始字节、request ID和时间 | 完整保留的内存事务日志；用于定位超时请求 |
| 日期记录JSON | 已落盘的摘要与原始点 | 可备份或导入另一浏览器 |

建议每轮STOP确认待机后立即导出。清除浏览器网站数据会删除日期记录；GitHub上传代码
不会备份当前浏览器的行走记录。刷新页面会丢失尚未下载的内存遥测和日志。

## 8. 常见问题与处理

| 现象 | 先检查 | 处理顺序 |
| --- | --- | --- |
| localhost拒绝连接 | 服务窗口/4173端口 | 启动npm.cmd run local，再刷新/exo |
| 配对后GATT失败 | 其他客户端占用、主控供电、连接阶段 | 断开其他客户端，重试已选设备；保留具体错误 |
| Product Service发现失败 | 固件身份、是否重启或断连 | 重新选择正确设备，核对版本；不把旧固件接口当产品服务 |
| BLE写入3秒未完成 | 最后一条TX、供电、当时遥测负载 | 保存BLE JSONL；写入结果不明时不反复发送START/校准 |
| 校准/START灰色 | 按钮下方原因和主控状态 | 先处理反馈/故障，再确认方向与本次零位、配置读回 |
| 实时图空白 | 是否推流、通道是否选择、末帧时间 | 开始遥测；区分未采集、缺帧和无效通道 |
| 脉冲结束后没有下一次 | 左右脉冲状态、复位角、新事件/周期可信度 | 核对真实角度和退出原因；不靠固定定时器重复助力 |
| 角度更新、助力突然长期消失 | 主控ERROR、输出门、CAN计数及锁存故障 | 保留故障记录，排除原因后再恢复，不自动重新START |
| USB接着稳定、拔掉异常 | 外部供电、共地、RX逻辑电平及CAN波形 | 测量验证；蓝牙本身不依赖USB串口数据 |

2026-10-13实例：最近锁存故障为CAN_ERROR_PASSIVE，瞬间TEC/REC=0/133；固件TEC或
REC>=128会关闭运动输出并进入ERROR。随后CAN反馈恢复且REC降至0，ERROR仍锁定，
不会突然自行恢复助力。这解释了角度继续更新、助力最新值为“—”。这是失败证据，
不是CAN链路已经修好的结论，详见[原始诊断与后续检查](../phase10/PHASE_10_ASSIST_INTERRUPTION_20261013.md)。
