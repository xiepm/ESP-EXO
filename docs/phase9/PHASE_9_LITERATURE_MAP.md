## 2. 当前髋角峰值代理

### 2.1 当前实现到底估计了什么

`HIP_EVENT_TBE` 使用人体髋坐标下的左右角度和角速度：

```text
髋速度趋势正 -> 负  => 髋屈曲峰
同侧相邻屈曲峰间隔 => 候选周期 T
phase                => (当前时间 - 最近屈曲峰时间) / T
```

它适合在只有两个 RS01 编码器的当前硬件上建立统一相位输出合同和回放基础，但有明确假设：

- 穿戴者运动近似周期，髋屈伸摆幅能跨过固定阈值；
- 左右人体方向映射和 RAM 零位正确；
- 同侧髋屈曲峰可以作为稳定周期原点；
- 周期落在 `0.5~3.0 s`，至少两个稳定周期后才锁定；
- 启停、转弯、拖步、病理步态和小幅挪步可能降低置信度或无法锁定。

最重要的语义限制：髋屈曲峰不能直接等同于足跟着地，当前相位也不是由力平台定义的标准 gait event
相位。若实验要求 heel strike/toe off 误差，必须增加相应参考传感器或标注系统。

## 3. 步态估计器的可替换映射

### 3.1 统一替换合同

无论采用哪种文献方法，固件边界应保持：

```text
exo_sensor_snapshot_t
        |
        v
[固定内存、确定时间的 estimator backend]
        |
        v
exo_gait_estimate_t
  estimator_id / state / phase_origin
  left_phase_01 / right_phase_01
  period / cadence / confidence
  valid_flags / quality_flags / source sequence
```

当前头文件预留了 `ADAPTIVE_OSCILLATOR`、`PLANTAR_DURATION_HMM`、`JOINT_LSTM` ID，但代码尚未建立可选
后端工厂；真正接入时需要增加编译期静态 dispatch、各自状态结构和测试，不应只修改枚举值。

### 3.2 自适应振荡器

| 项目 | 映射建议 |
|---|---|
| 目标 | 从周期髋角/角速度在线收敛频率与连续相位，改善固定事件间线性外推在速度变化时的表现 |
| 最小输入 | 左右髋角度或角速度、可靠时间戳；可选大腿 IMU |
| 输出映射 | oscillator phase -> `left/right_phase_01`；frequency -> period/cadence；幅值/收敛误差 -> confidence |
| 固件状态 | 每侧振荡器相位、频率、幅值、耦合/误差积分，使用固定大小结构 |
| reset 条件 | `reset_epoch` 变化、时间/序号回退、长时间输入无效；不能继承旧零位历史 |
| 验收重点 | 收敛时间、速度突变跟踪、相位单调性、停走退锁、不同步态频率和非周期扰动 |

文献索引：`膝关节外骨骼机器人助力控制策略与人在回路优化研究_王志鹏.pdf`。该文可用于确认振荡器
公式和快速收敛思路，但其关节对象、输入信号和参数不能未经重标定直接搬到本项目髋关节。

### 3.3 足底时序与 HMM

| 项目 | 映射建议 |
|---|---|
| 目标 | 用足跟/前掌接触或足底压力判断支撑、摆动及关键事件，再由事件间持续时间计算连续相位或由 HMM 输出状态 |
| 必需输入 | 左右足接触/压力；若做模式识别，通常还需 IMU、关节运动量或特征窗口 |
| 当前缺口 | snapshot 只预留 `FOOT_CONTACT`/`LOWER_LIMB_IMU` mask，没有实际样本字段、驱动、标定和时钟对齐 |
| 输出映射 | 离散状态 -> estimator state/quality；heel strike 等事件需新增明确 origin/event 线码；持续时间 -> phase/period |
| 固件状态 | 去抖、阈值/归一化、左右事件历史；HMM 的转移/发射参数和固定窗口/前向概率 |
| 验收重点 | 与力平台或人工标注的事件误差、误触发、不同鞋/体重/地面、传感器掉线和单双脚异常 |

文献索引：

- `高能效康复下肢外骨骼系统控制算法及实现研究_张龙.pdf`：足底压力与步态相位/刚度切换方向；
- `基于健患侧步态耦合的下肢外骨骼人机协同控制方法研究_张鹏.pdf`：足底压力区分支撑/摆动和双侧耦合；
- `基于可穿戴数据人体下肢模式与相位识别的运动意图研究_王毓.pdf`：足底压力、IMU 与可穿戴模式/相位识别；
- `下肢主动助力外骨骼感知与规划技术研究_王嘉琪.pdf`：HMM 运动模式识别及连续相位相关方法。

这里的“足底时序/HMM”是两种可组合但不同的后端：阈值时序可以不使用 HMM；HMM 也不能在没有
训练/标定参数和输入特征定义时写成已实现。

### 3.4 关节 LSTM / 时序网络

| 项目 | 映射建议 |
|---|---|
| 目标 | 从多关节/IMU/足底等时间窗直接估计落地事件、连续相位或运动意图 |
| 最小输入 | 取决于论文；必须复现通道定义、单位、归一化、窗口长度和采样率，不能只给两个髋角就沿用原模型 |
| 当前缺口 | 当前仅双髋数据；没有模型权重、固定序列缓冲、推理 arena、量化方案和最坏执行时间证明 |
| 输出映射 | 网络 phase -> `phase_01`；事件头 -> origin/event；不确定性/验证误差 -> confidence/quality |
| ESP32 部署 | 优先离线训练 + 量化模型 + 静态 arena；推理必须纳入唯一 100 Hz 任务并测量 WCET 和栈/内存 |
| 验收重点 | 受试者外泛化、速度/坡度/转弯、训练测试隔离、延迟、单调性、丢帧、定点误差和回放确定性 |

文献索引：

- `下肢主动助力外骨骼感知与规划技术研究_王嘉琪.pdf`：双 LSTM 依次估计落地事件和连续步态相位；
- `基于健患侧步态耦合的下肢外骨骼人机协同控制方法研究_张鹏.pdf`：LSTM 时序预测/分类和健患侧信息；
- `髋关节外骨骼康复机器人的性能分析与控制策略研究_贾增钰.pdf`：LSTM 运动意图预测；
- `基于EEG和sEMG的下肢外骨骼人机交互策略与方法研究_李文举.pdf`：sEMG 时序网络，适合作为未来肌电输入方向，不是当前关节相位模型。

## 4. 高层助力策略的可替换映射

### 4.1 主动相位助力曲线 `PHASE_PROFILE`

未来相位曲线策略应只消费已经发布的步态结果，不在策略内部重新读取 RS01 或自行估计一套相位：

```text
left/right phase + confidence + profile_id + L/R level
                         |
                         v
只读 Flash 中的版本化曲线/参数
                         |
                         v
一对人体髋关节五元建议
```

当前静态描述符已经声明：左右髋运动量、左右 phase 和 confidence 必需，最低 confidence 为 `0.40`，
可变工作区预留 32 byte。但 `implemented=false`，没有曲线表、插值器、幅值定义、输出单位或真实控制连接。

接入阶段至少还需确定：

- 相位原点是否为髋屈曲峰、heel strike 或论文定义的 0%；
- 左右曲线是否独立，是否允许健侧相位驱动患侧；
- 曲线输出是前馈力矩、位置偏置、阻抗参数还是完整五元；
- 0~100% level 如何缩放，是否线性，以及 profile 版本如何与文献实验条件对应；
- 相位失效、confidence 降低、单侧可用时的退化输出合同；
- 从 SHADOW 到 ACTIVE 的输出连接与阶段 8 控制器如何仲裁。

文献索引：`膝关节外骨骼机器人助力控制策略与人在回路优化研究_王志鹏.pdf`、
`高能效康复下肢外骨骼系统控制算法及实现研究_张龙.pdf`、
`行走助力外骨骼机器人设计及驱动力矩优化方法研究_李洪武.pdf`。这些研究可以提供助力时机、曲线或
优化目标的思路，但必须重新核对关节、传动形式和实验对象。

### 4.2 按需辅助 `AAN_RESIDUAL`

按需辅助不是把固定相位曲线乘一个手机百分比。它至少需要一个可观测的“使用者能力/任务误差/人机
交互”量，再据此调整基础助力：

```text
phase-profile baseline
        +
interaction/performance residual -> assistance adaptation
        |
        v
bounded SHADOW suggestion
```

当前描述符要求：左右髋运动量、左右 phase、confidence>=0.60 和
`EXO_SENSOR_INTERACTION_TORQUE`，并预留 64-byte 可变状态。当前硬件没有交互力矩通道，所以即使将
mode/strategy 配为 AAN + SHADOW，也只会报告 `STRATEGY_NOT_IMPLEMENTED` 或传感依赖不满足，不会生成
可用建议。

未来可能的 residual 定义包括：

- 人机交互力矩相对于透明/目标交互的残差；
- 实际轨迹相对于参考轨迹的误差及其周期趋势；
- 健侧预测与患侧表现的差异；
- sEMG/意图估计与实际输出之间的差异。

这些定义不能混为同一个“残差”。选择前必须写明可测量量、符号、单位、滤波、延迟、归一化、学习/适应
律和停止时的状态清除规则。

文献索引：

- `面向主动康复训练的下肢外骨骼结构设计与交互控制研究_王刚.pdf`：主动参与和按需辅助方向；
- `面向偏瘫患者的下肢外骨骼机器人助力过程状态识别与人机协同控制_柏昀旭.pdf`：人机交互力矩、状态识别与协同控制；
- `卧式下肢康复外骨骼机器人的位置_力交互控制方法研究_房倩倩.pdf`：动力学/数据驱动力矩残差补偿；
- `基于健患侧步态耦合的下肢外骨骼人机协同控制方法研究_张鹏.pdf`：健患侧耦合信息来源。

其中房倩倩文献的“力矩预测残差补偿”与产品 AAN 的“需要多少帮助”并非天然同义，只能作为 residual
建模方法参考，不能直接把论文结论迁移为本项目 AAN 效果。

## 5. 传感需求矩阵

| 后端/策略 | 双髋编码器 | 电机估算力矩 | IMU | 足底接触/压力 | 独立交互力矩 | sEMG | 当前可部署性 |
|---|---:|---:|---:|---:|---:|---:|---|
| HIP_EVENT_TBE | 必需 | 否 | 否 | 否 | 否 | 否 | 已实现 |
| 自适应振荡器（髋输入） | 必需 | 否 | 可选 | 否 | 否 | 否 | 未实现，但现有输入可做原型 |
| 足底阈值时序 | 可选 | 否 | 可选 | 必需 | 否 | 否 | 缺硬件/快照字段 |
| 足底/IMU HMM | 可选 | 否 | 常需 | 常需 | 否 | 否 | 缺硬件、模型和训练数据 |
| 关节 LSTM | 取决于论文 | 否 | 常需 | 可选 | 可选 | 可选 | 缺通道、模型和推理资源证明 |
| PHASE_PROFILE | 必需 | 否 | 间接 | 间接 | 否 | 否 | 仅描述符占位 |
| AAN_RESIDUAL | 必需 | 不可替代 | 间接 | 可选 | 当前设计必需 | 可选 | 仅描述符占位，当前传感不满足 |

“间接”表示策略不直接读取原始传感器，但上游步态估计可能依赖它。

## 6. 推荐的升级顺序

1. 保存阶段 9 原始双髋快照与外部基准事件，先建立可重复回放数据；
2. 用同一数据同时跑 HIP_EVENT_TBE 和候选自适应振荡器，比较锁定时间、事件/相位误差和失效行为；
3. 接入足底/IMU 时先扩展统一快照和时钟质量，再接算法，不能直接在 estimator 中读新驱动全局变量；
4. 若选 LSTM，先在 PC 离线复现论文预处理/模型，再量化到 ESP32，并保留非网络后端作为对照；
5. 在 estimator 输出合同稳定后实现 `PHASE_PROFILE`，先 SHADOW 对齐曲线和符号；
6. 只有独立交互量可测且完成标定后，再实现 `AAN_RESIDUAL`；
7. 每个后端都先通过回放、WCET、内存和真机只读观察，再讨论真实输出。

## 7. 复现声明模板

为避免后续报告夸大，建议使用以下分级措辞：

- “参考某文献的接口思想”：只借鉴输入/输出或模块边界；
- “实现某文献的算法变体”：公式或网络有修改，需列出差异；
- “复现某文献方法”：输入、参数/训练、实验条件和指标均有证据对应；
- “验证本项目实现”：只证明本固件在本硬件/数据上通过验收，不等于复现论文结论。

阶段 9 当前只能写为：**实现了基于双髋编码器峰值事件的工程相位代理，并为文献算法建立了可替换输入、
输出和 SHADOW 策略边界。**
