# 0.10.8 角度助力峰值5 N·m、上升速率10 N·m/s

状态：`SOFTWARE PASS; FLASH PASS; WEB 5NM WRITE/READBACK PASS; 5NM MOTION/HUMAN HIL NOT RUN`。

冻结后用户明确当前动力已断电并要求继续，0.10.8冻结产物已烧录，三处哈希校验及IDLE/运动输出0检查通过。网页重新配对后INFO确认0.10.8/0x3F7F，通过网页按钮写入并读回ANGLE_THRESHOLD、5.000 N·m、10.00°、双侧0%/DISABLED；串口独立确认保存峰值5.000 N·m、START请求及运动输出仍0。见[0.10.8部署记录](PHASE_10_0_10_8_DEPLOYMENT_20261010.md)。

用户要求将助力峰值设为5 N·m；随后将上升速率最终指定为10 N·m/s（覆盖先前3 N·m/s要求）。本次针对已选择的单向前抬ANGLE_THRESHOLD策略。阶段10整体仍未完成，阶段11未完成。

## 参数和控制边界

| 项目 | 0.10.8行为 |
| --- | --- |
| 可配置峰值M | 0–5.000 N·m，精度0.001 N·m；5000 mN·m=5 N·m |
| 单侧稳定建议力矩 | M×本侧等级/100；M=5时，0/10/50/100%=0/0.5/2.5/5 N·m |
| 最大上升速率 | 10 N·m/s；正常10 ms周期最多增加0.100 N·m |
| 周期抖动 | 按实际采样间隔计算预算，最多取10 ms；5 ms最多0.050 N·m，迟到不累积大阶跃 |
| 渐入与退出 | 保留200 ms五次曲线平滑起步；达到5 N·m至少约0.5秒；q≤T−1°立即清零 |
| 新动作门禁 | 每次激活/失效恢复后，须先低于退出阈值，再出现q>T的新前抬 |
| 执行方式 | DISABLED不输出；SHADOW可建议5 N·m、实际附加助力0；ACTIVE通过门禁后才叠加 |
| 默认值 | 默认峰值仍0.500 N·m、双侧0%、DISABLED；升级不自动升高参数或START |

原PHASE_PROFILE工程曲线仍受0.500 N·m边界及原0.010 N·m/10 ms斜率限制；没有提高它的输出范围。基础DAMPING+CONSTANT要求、人体角度坐标、静态工作区、唯一100 Hz任务和最终CAN运动出口保持现有架构。

本轮START同时锁存策略、执行状态、activation epoch和最大力矩。控制器检查纯torque_ff增量及合成后的最终绝对值，须不超过本轮配置峰值和5 N·m总边界；缺少ACTIVE策略、NaN/Inf、越限均拒绝。旧合成器入口仍限0.5 N·m。配置0.1 N·m时，不能因为全局支持5 N·m就接纳伪造的0.101 N·m建议。

RS01本地手册`RS01User Manual260713.pdf`的协议示例定义力矩编码范围±17 N·m，`limit_torque`参数范围0–17 N·m。5 N·m可由已有协议编码；这不证明实际关节力矩准确性、持续负载能力或人体助力安全性。主机夹具只替代RTOS和硬件映射/发送，未测机械输出。

## BLE与运动页

固件版本0.10.8，角度策略版本2，新增capability bit13 `ANGLE_ASSIST_5NM`。0x1D仍为原12-byte原子配置：模式/运行方式/等级、u16LE mN·m和u16LE 0.01°阈值。旧0x19和相位策略仍拒绝超过500 mN·m。GET_ASSIST_TORQUE_LIMIT格式不变，0.10.8报告全局5000 mN·m；网页同时按所选策略收紧范围。

网页要求INFO能力声明与读回上限一致，保存前再次查询当前设备上限，保存后逐项读回确认；支持旧0.10.7的0.500 N·m范围。未连接时5 N·m输入仅是草稿，不能显示为已写入。切回相位策略只收紧草稿至0.500，不隐式改变主控参数。上升速率说明由实际设备能力选择：0.10.7仍显示1 N·m/s，0.10.8显示10 N·m/s。

## 部署和未完成事项

候选`candidate-0.10.8`冻结时未烧录。升级会复位主控并清除RAM零位/助力配置，需要先确认当前两台电机动力已断开；保留USB/CAN模块供电和方向NVS，不整片擦除。烧录后先检查INFO、IDLE、默认关闭、运动输出0，再通过网页保存M=5.000 N·m、T=10°、双侧0%、DISABLED并读回。上电后重新核对反馈及本次穿戴中立位，再采集RAM零位。

本次改参数不自动START或使能。先观察跨越阈值的建议及实际为0，再按已记录的分级流程验收低等级ACTIVE；完整5 N·m人体输出未验收。后续实际烧录、网页读回和运动证据必须单独记录，不能覆盖冻结时的未烧录状态。
