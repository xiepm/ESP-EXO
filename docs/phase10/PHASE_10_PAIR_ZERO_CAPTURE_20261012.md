# 0.10.11 当前双髋成对零位校准

状态：`SOFTWARE PASS; NOT FLASHED; TARGET PAIR ZERO HIL NOT RUN`。
本条不改变阶段10整体未完成、阶段11未完成的结论。

## 问题与范围

用户截图中选择“重新校准”，左髋0.00°、右髋20.51°，且两侧已有有效零位。
代码核对确认原网页先发送LEFT的`CAPTURE_ZERO`、再发送RIGHT的同名请求，最终只检查
`zeroValid/jointValid`，没有核对人体角是否接近0°。这允许已有有效旧零位的读回通过
校准成功检查；分侧请求失败也可能留下新旧混合的一对零位。
截图不能确定当次是否点击成功、是否中途移动或发生通信超时，因此不能据此认定现场
偏差的唯一成因。此次修复关闭上述代码缺口，不把历史反馈当成当前设备状态。

## 最终行为

- **重新校准**：确认当前双髋中立静止后，单次BLE请求采集两侧当前位置，两个RAM零位
  在同一个短临界区提交；旧零位有效与否不影响本次覆盖。
- 固件先核对映射、方向、两侧新反馈（年龄≤50 ms）、REST、无故障、速度≤5°/s。
  提交前复核epoch/序号/时间没有倒退、预检到采集之间位移≤1°、双侧采样时间差≤20 ms。
  任一侧拒绝时两侧RAM零位均不更新；采集来源的连续角、周期角、时间、序号、epoch一起保存。
- 网页收到ACK后读取两侧关节、两侧原始角和偏置及最终IDLE状态。必须两侧均有效、
  新鲜、在线，人体角及`原始连续角−软件偏置`绝对值均≤0.5°，才显示本次校准成功。
  容差容纳协议量化和站立微动；页面持续显示真实反馈，校准后移动不会仍显示0°。
- **沿用上次零位**：恢复NVS候选偏置，保留原有±5°姿态门禁，不把当前姿态强制变为0°。
- 勾选保存才在双侧校准读回通过后另外执行NVS保存。保存失败明确区分“本次RAM已校准”
  与“候选未确认保存”；未勾选时旧候选保持不变。
- 校准失败、ACK丢失或STOP抢占均不自动重复采集，不用已经有效的旧标志推断成功。
  没有新增控制任务、CAN运动出口、使能命令或RS01机械置零。

## 协议与兼容

沿用BLE v1 `0x1F SAVED_ZERO_ACTION`，payload仍为`[action, confirmed=1]`，请求6 B。
新增`action=3 CAPTURE_PAIR`，原SAVE_CURRENT=0、RESTORE=1、FORGET=2保持不变。
原`0x12 CAPTURE_ZERO(side)`保留为明确分侧的工程调试入口，不用于产品双髋校准按钮。
16位能力字段已分配完，此新增动作由网页核对已知版本**0.10.11**以及校准读回/保存零位
能力启用；0.10.10及更早版本不会收到action=3，已有沿用功能仍可用。
