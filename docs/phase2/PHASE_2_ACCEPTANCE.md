# 阶段 2 验收：RS01 驱动及主动反馈

## 结论

阶段 2 于 2026-08-06 通过。固件已从泛型 RobStride 驱动迁移为 RS01 专用驱动，
A/B 使用独立静态反馈对象，上电自动请求约 100 Hz 主动反馈；UART、BLE、TWAI
和原有双电机正弦阻抗基线均已在实机通过。

本阶段没有建立髋关节左右映射、安装方向、软件零位、产品状态机、唯一控制任务或
产品遥测，也没有增加实验模块。

## 主动反馈实机验收

### 手册与产品固件差异

手册称周期流为 type 2、`0x7026=1` 表示 10 ms。当前两台 RS01 的实测结果是：

- 持续周期帧为 type 24；type 2 只在启动或切换请求附近出现；
- `0x7026=1` 时最近帧间隔约 15 ms，即约 66.7 Hz；
- `0x7026=0` 时 A/B 最近帧间隔分别为 9.871 ms 和 10.009 ms；
- 因此当前产品驱动把请求 10 ms 映射为寄存器值 0，并保留 type 2/type 24
  分项计数。

### 约 100 Hz、隔离、离线和恢复

在电机未使能、没有运动命令时测得：

| 项目 | A | B |
|---|---:|---:|
| `0x7026` 读回 | 0 | 0 |
| 计数差实测频率 | 101.05 Hz | 99.50 Hz |
| 稳态最近帧间隔 | 9,871 us | 10,009 us |
| 无效帧计数 | 0 | 0 |
| 关闭后反馈年龄 | 1,019,429 us | 1,009,477 us |
| 关闭后 `Online` | no | no |
| 重新开启后 `Online` | YES | YES |

单独关闭 A 时，B 的 type 24 计数继续增加 400；单独关闭 B 时，A 的计数继续增加
401。两次测试均超过 100 ms 在线超时阈值，证明 A/B 状态没有串扰。重新开启后，
对应执行器恢复计数和在线状态。测试前后 TWAI 的 TX/RX error、TX failed、bus
error、arbitration lost 和 RX missed 均为 0。

### 60 秒持续运行

主动反馈连续运行 60 秒，无异常复位、看门狗、断言、Brownout 或 BUS_OFF：

| 项目 | A | B |
|---|---:|---:|
| type 24 计数 | 6,174 | 6,292 |
| 最近帧间隔 | 10,134 us | 10,015 us |
| 在线/请求上报 | YES / ON | YES / ON |
| 无效帧 | 0 | 0 |

结束时全部 TWAI 错误和 RX missed 仍为 0。

## UART 与 BLE 回归

UART 的启动标志、`help`、`motor_type`、A/B `status` 和 `can_status` 通过；
`motor_type` 显示 RS01 正确量程：位置 ±12.57 rad、速度 ±44 rad/s、转矩
±17 N·m、Kp 0..500、Kd 0..5。

BLE NUS 完整验证了服务、欢迎信息、`help`、`motor_type`、`motor A/B`、两台
`status` 和 `can_status`。断开后 3.235 秒重新出现，第二次连接及 `can_status`
通过。CAN RX 任务不再主动等待 BLE 通知；删除该阻塞路径后，两轮 BLE 测试的
`RX missed` 均为 0。阶段 2 只支持按需查询，连续产品遥测留给阶段 10。

## 双电机阻抗回归

执行 3 轮、每轮 10 秒的原有正弦阻抗基线，3/3 通过：

- 每轮 A/B 各记录 50 个节流后的反馈样本，覆盖 9.8 秒；
- 第 1 轮拟合频率 0.496 Hz、周期 2.016 s、相位差 179.45°；
- 第 2 轮拟合频率 0.498 Hz、周期 2.008 s、相位差 178.70°；
- 三轮均观察到 A/B 运动、中心位置反馈、正常启动和失能停止；
- 三轮均无 `No feedback`、BUS_OFF、复位、断言或看门狗；
- 每轮及最终 TWAI 全部错误计数和 RX missed 为 0。

参考生成仍是原有 100 Hz 定时器、0.5 Hz 正弦、五次渐入和原阻抗参数；这里只迁移
了驱动调用，阶段 4 和阶段 7 才分别处理唯一控制任务和参考/控制律拆分。

## 未验证边界

- 测试期间没有人为触发电机故障，因此没有收到 type 21。其两个 `uint32` 暂按
  little-endian 解析，但字节序和全部位映射尚未获得故障帧实证。
- 电机保持私有协议；MIT 参数、DLC5/8 故障兼容路径只完成静态审查和构建，未在
  本轮切换电机协议实测。
- `set_id` 会永久改变电机通信配置，本轮没有执行；运行时映射和冲突拒绝路径已做
  代码审查与构建验证。
- 当前产品固件的 `0x7026=0` 覆盖与手册不一致；更换 RS01 固件版本后必须重新
  测量，不得无条件沿用。

这些边界已明确记录，不影响阶段 2 的私有协议主动反馈、A/B 隔离和现有控制基线
验收。阶段 2 验收结论为 **PASS**。
